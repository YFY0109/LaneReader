# LaneReader

> **A Dance of Fire and Ice（冰与火之舞）的 4K 下落式辅助读谱 mod。**
> 直接读取游戏内存里已经构建好的谱面，渲染成 4 条下落轨道，并用两套算法自动排键。

面向 ADOFAI 3.3.1 / Unity 6000.3.10f1 / Mono / UnityModManager 0.32.4。

---

## 功能

| 功能 | 说明 |
|---|---|
| 实时读谱 | 从游戏内存读已构建的谱面，**不需要谱面文件**，兼容任意自制谱 |
| 4K 视图 | 4 条轨道 / 判定线 / 判定框 / 键位标签 `D F J K` |
| 打击弹跳 | 音符到线时的弹跳反馈，纯时间驱动，不读游戏判定 |
| 暂停保留 | 暂停时叠加层留在屏幕上、音符停在原地；「按任意键开始」那屏只有静态框 |
| 小节线 | 每拍细线、每小节粗线；节拍按 TBPM 铺，跟着谱面的加速/减速变化 |
| 轨道长度可定 | 轨道长度是一个独立设置（默认 1620px = 1.5 屏，`0` = 一直画到屏幕顶）；**音符和小节线也从轨道顶端开始出现**，所以它同时决定你有多久的反应时间 |
| 调色板 | 轨道底色/边框、音符/音符边框、判定线、判定框、键位标签、细小节线/粗小节线**各自带 RGBA**；轨道与音符可「四轨单独配置」或一键统一。任何主题都不会把轨道和音符设成同一个颜色（拉满轨道透明度也能分清） |
| 主题预设 | 七个一键套用：经典蓝橙、亮底黑线、霓虹紫青、黄金黑底、四轨彩虹、极简纯白、纯黑底经典白线（背景全不透明） |
| 全屏纯色背景 | 默认关；打开后用一整屏纯色盖住游戏原本的画面，默认黑色 50%，颜色和透明度都可调 |
| 判定线 | 可整个关掉；也可以不横跨全屏，改成按屏宽百分比居中显示 |
| 面板 | 分区可折叠（标题是 ▶/▼ 按钮，不是开关圆圈）；**分区按层级缩进**；**每个滑块都能直接填数字**；颜色行支持 `RRGGBBAA` 十六进制输入 |
| 实验性平滑下落 | 默认关；给音符补一层按前几帧位置的淡拖尾（有自定义图片时拖尾也用那张图），缓解高速下落的一格一格感；拖尾会沉进判定线里被它吃掉，不会跟着音符一起消失 |
| 实验性 3D 轨道 | 默认关；把整个下落放进一台针孔相机：灭点正好在轨道顶端（= 判定线上方「轨道长度」那么远），四条轨道收敛到同一个点，轨道边缘是精确的直线（无锯齿），音符是**贴在轨道上的板**——越往上沿轨道方向越压扁、边缘随轨道收敛，而不是整体缩小 |
| 长按 | 默认开；读 `holdLength` 画长按长条，**末端始终接住下一颗音符**（和游戏自己的画法一致）；开头过线后长条留在原地被判定线慢慢吃掉、开头的打击弹跳一直顶到尾巴音符到来才缩小消失；拆手序会把松手当成一颗键并强制与长按开头同轨 |
| 娱乐（实验性） | 默认关；轨道乱飞 / 轨道持续旋转 / 四花瓣（四条轨道底边中心重合在判定线中点，朝四个互相垂直的方向伸出去）——纯好玩，不影响读谱 |
| 外观可调 | 明暗背景、音符边框、轨道背景透明度（0~100%）、水平偏移 |
| 自定义音符图片 | 用 png/jpg（含 alpha）替换音符；**有图时就只画那张图**（不画原来的音符和边框），透明就是透明；拖尾也用同一张图；长按线条可以另外指定一张图 |
| GitHub | `Info.json` 里带 `HomePage`，UMM 的 mod 列表会出现可点击的网址按钮；面板「其它」里也有一个按钮 |
| 整体旋转 | 0~360°，整个叠加层绕判定线中点旋转 |
| 两套手序 | 「AdoFalling 原版」与「拆手序」可切换 |
| 诊断日志 | 可关闭；排键、拍网格、每帧门控都有一行可对照的日志 |
| 显示帧数 | 默认**关**；打开后在判定线下方显示 `fps + 帧间隔(ms)`，和游戏本身同一套帧 |

## 自定义音符图片

把图片（png / jpg）放到 `Mods\LaneReader\`，面板「显示 → 用自定义音符图片」打开，
路径默认 `note.png`（相对路径基于 mod 目录，也可以填绝对路径）。
安装目录里带了一张演示图 `note.png`（圆角胶囊、半透明填充），可以直接开来试。

- png 的 alpha 生效；jpg 没有 alpha
- **有图时就只画那张图**：不画原来的音符色块，也不画音符边框
- **图片按原样画**：没有「用轨道颜色着色」这种功能了，图片是什么颜色就是什么颜色
- 「保持宽高比」默认开（contain 居中，按**平面**音符框算，所以透视下也是这个样子被投影）；
  关掉就拉伸填满音符框
- 「平滑下落」的拖尾重影也用这张图（所以补帧的拖尾和音符长得一样）
- 「长按线条用自定义图片」是**另一张**图（默认 `hold.png`）：沿长条方向拉伸铺满，
  宽度仍按「长按线条」的粗细比例；按原样画，长按的颜色和透明度不再乘上去
- 换图不用重启：最多 1 秒后自动重读，面板上还有「重新加载」按钮
- 面板会显示状态（`已加载 256x64` / `找不到文件` / `解码失败`），日志里对应
  `note image: ...` / `hold image: ...`

## 安装

UnityModManager 已就位的前提下：

1. 把 `LaneReader.dll` 和 `Info.json` 放进 `<游戏目录>\Mods\LaneReader\`
2. 启动游戏，UMM 的 mod 列表里会出现 `LaneReader (4K view)`

设置面板在 UMM 的 mod 设置里（全部手写 `GUILayout`，**不依赖 UMM 的自动绘制**
—— 那套在这台安装上对自绘面板的 mod 无效）。

---

## 构建

```powershell
Set-Location LaneReader
powershell -ExecutionPolicy Bypass -File .\build.ps1            # 只编译
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Install   # 编译并部署到游戏
```

- 用 `csc.exe`（.NET Framework 4.0.30319）编译，`/langversion:5`（**不能用 C# 6+ 语法**）
- **部署前必须完全退出游戏**，否则 DLL 被占用（`user-mapped section open`）
- 构建产物 `LaneReader/build/` 不入库

## 默认设置（v0.3.0）

| 设置 | 默认 | 说明 |
|---|---|---|
| 流速 | `1000 px/s` | 1080p 基准像素，实际按屏幕高度缩放 |
| 手法 | **拆手序** | 可切回「AdoFalling 原版」 |
| 最大硬抗 BPM | `850` | 手序的标定旋钮，见下 |
| 轮指方向 | 外轮 `K J D F` | 可切内轮 `J K F D` |
| 轨道长度 | `1620 px`（= 1.5 屏） | 固定长度；`0` = 旧行为（一直画到屏幕顶端）。默认长于屏幕，所以音符是从屏幕顶上滑进来的 |
| 判定线 | **显示**、横跨全屏 | 开关和长度都在「布局」里，紧挨着判定线高度 |
| 长按支持 | **开** | 长条 = 从开头音符一直连到下一颗（游戏自己的画法）；没长按的谱完全不受影响 |
| 全屏纯色背景 | 关 | 开了就是黑色 50%，用来挡住游戏原本的画面；颜色和 A（透明度）可调 |
| 音符边框 / 小节线 | 开 | 可关 |
| 自定义音符图片 / 整体旋转 | 关 / `0°` | 都不影响原来的外观 |
| 颜色 | 经典蓝橙（暗底白线） | 即旧版的观感；可在「外观 / 颜色」里逐项改或换主题（共 7 个预设） |
| 平滑下落（实验） | 关 | 开了才有拖尾；层数 4、浓度 0.45 |

> 已经存过 `Settings.json` 的机器会继续使用自己保存的值，不会套用新默认。
> 想用新默认：面板「其它 → 恢复默认」再「保存」，或者删掉 `Mods\LaneReader\Settings.json`。
>
> **关于「最大硬抗 BPM = 850」**：本机读不到谱面 BPM，拆手序会落到自己的兜底 800 BPM。
> 上限设成 `850` 时 800 **不会**被减半，base = **800**；旧的 `506` 会把它减半成 base = **400**。
> base 越大，一个窗口里塞得下的音符越少，轮指就越少、换手也越少 —— 这是手感差异的来源。

## 手序（排键）说明

**AdoFalling 原版**：相邻音间隔小于「轮指窗口」就轮指（轨道沿当前方向 ±1 走格），
否则在两根食指之间交替。

**拆手序**（默认，移植自 [ReADOFAIMacro](https://github.com/TonyLimps/ReADOFAIMacro)）：

1. 把谱面 BPM 归一化（翻倍到 >550、减半到 ≤1100、超过硬抗上限再减半一次）
2. 按归一化的一拍把音符切成「窗口」：窗口内音符数越多，说明这拍越挤
3. 窗口内的音符数决定指法（1 个 = 单指，2 个 = 同一只手两根手指＝外轮，更多则对半分给两手）
4. **窗口长度决定下一个窗口换不换手** —— 这一条是"拆手"的核心：
   一拍左右换手、更长则不换、长音回主手单指重复

完整的推导、4K 适配表、离线对比验证方法，以及**实测调好的那套标定**（为什么
`ApplyHandSplit` 里那一行 BPM 来源不能改）都写在 [`HANDOFF.md`](HANDOFF.md) §14。
